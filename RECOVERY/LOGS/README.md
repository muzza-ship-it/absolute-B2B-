# RECOVERY/LOGS/

The canonical, authoritative recovery log is `docs/RECOVERY_LOG.md` (kept
in `docs/` alongside the other process documentation so it's easy to find
with the rest of the project docs). This folder exists as the structural
home for logs per the requested RECOVERY/ layout, and can hold future
batch-specific or dated log exports/snapshots if the audit trail ever
needs to be split — but until then, treat `docs/RECOVERY_LOG.md` as the
single source of truth, not this folder.
